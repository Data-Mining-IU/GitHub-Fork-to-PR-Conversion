\section{Modeling}

This phase implements CRISP-DM Stage 4 using the prepared integrated dataset in \texttt{src/data/modeling\_dataset.parquet} (or \texttt{.csv} fallback). It evaluates the modeling criteria that are directly available from the exported 90-day dataset and documents the remaining label-window sensitivity requirement.

\subsection{Select Modeling Technique}

\subsubsection{Modeling Objectives}

Two predictive tasks are modeled:
\begin{itemize}
    \item \textbf{Classification:} predict whether a repository-season has at least one converted fork (\texttt{has\_conversion}).
    \item \textbf{Regression:} predict the conversion intensity (\texttt{fork\_conversion\_rate}).
\end{itemize}

This dual formulation supports both operational triage (high vs.\ low conversion potential) and continuous forecasting of conversion magnitude.

\subsubsection{Chosen Techniques}

The modeling stage compares baseline and non-baseline methods:
\begin{itemize}
    \item \textbf{Naive baselines}
    \begin{itemize}
        \item Classification: majority-class predictor.
        \item Regression: mean conversion-rate predictor.
    \end{itemize}
    \item \textbf{Logistic Regression} for interpretable linear decision boundaries under class imbalance.
    \item \textbf{Random Forest} for non-linear interactions and robustness on skewed activity signals.
    \item \textbf{Gradient Boosting} (classification) as an additional non-linear ensemble benchmark.
\end{itemize}

\subsection{Generate Test Design}

\subsubsection{Validation Protocol}

\begin{itemize}
    \item Hold-out split: 80\% training / 20\% test.
    \item Random seed fixed at 42 for reproducibility.
    \item Classification split stratified by \texttt{has\_conversion}.
\end{itemize}

\subsubsection{Feature and Target Setup}

\begin{itemize}
    \item Input features include engineered activity signals (notably \texttt{log1p\_*} columns), season, and auxiliary non-leakage counters.
    \item Leakage-prone fields are excluded from predictors (\texttt{has\_conversion}, \texttt{fork\_conversion\_rate}, \texttt{n\_converted\_forks}, \texttt{repo\_name}).
    \item Numerical features are median-imputed and scaled for linear models.
    \item Categorical features are imputed with mode and one-hot encoded.
\end{itemize}

\subsubsection{Evaluation Metrics}

\paragraph{Classification}
\begin{itemize}
    \item Accuracy
    \item Macro-F1 (primary for imbalance-aware quality)
    \item Precision
    \item ROC-AUC (where probability outputs are available)
\end{itemize}

\paragraph{Regression}
\begin{itemize}
    \item Mean Absolute Error (MAE)
    \item $R^2$
\end{itemize}

\paragraph{Ranking quality}
\begin{itemize}
    \item Precision@10\%
    \item Lift@10\%
    \item NDCG@10\%
\end{itemize}

\subsection{Build Model}

\subsubsection{Implementation}

All models are implemented in \texttt{scikit-learn} pipelines in \texttt{src/Modeling.ipynb}:
\begin{itemize}
    \item shared preprocessing through \texttt{ColumnTransformer};
    \item model fitting on train split only;
    \item test predictions and metric computation on held-out data.
\end{itemize}

The following trained models are compared:
\begin{itemize}
    \item Classification: baseline, Logistic Regression, Random Forest Classifier, Gradient Boosting Classifier.
    \item Regression: baseline mean, Linear Regression, Random Forest Regressor.
\end{itemize}

\subsubsection{Hyperparameter Tuning}

Compact hyperparameter tuning is implemented with \texttt{RandomizedSearchCV}:
\begin{itemize}
    \item \textbf{Classification:} tuned Random Forest with macro-F1 objective.
    \item \textbf{Regression:} tuned Random Forest with MAE objective.
\end{itemize}
The tuned models are compared to untuned baselines on the held-out test set.

\subsection{Assess Model}

\subsubsection{Assessment Against Success Criteria}

The notebook directly checks whether:
\begin{itemize}
    \item Classification models outperform the majority baseline on Macro-F1.
    \item Regression models reduce MAE versus the mean baseline.
    \item Regression models achieve non-negative and preferably positive $R^2$ on the test set.
\end{itemize}

These checks align with the data mining success criteria defined in the business understanding stage.

\paragraph{Observed hold-out results (20\% test, random split)}
\begin{itemize}
    \item \textbf{Best classification model:} Gradient Boosting (\texttt{macro-F1} $=0.8514$, \texttt{ROC-AUC} $=0.9329$, \texttt{accuracy} $=0.8514$).
    \item \textbf{Classification baseline:} Majority predictor (\texttt{macro-F1} $=0.3425$).
    \item \textbf{Best regression model:} Random Forest Regressor (\texttt{MAE} $=0.0750$, $R^2=0.6313$).
    \item \textbf{Regression baseline:} Mean predictor (\texttt{MAE} $=0.1589$, $R^2\approx -0.0002$).
\end{itemize}

Thus, the core prediction criteria are satisfied on hold-out data: MAE improves vs baseline and $R^2$ is positive.

\subsubsection{Ranking Quality Results}

For the best classification model, repository-seasons are ranked by predicted conversion probability and evaluated in the top decile:
\begin{itemize}
    \item Precision@10\% vs random baseline rate.
    \item Lift@10\% (top-decile precision divided by global positive rate).
    \item NDCG@10\% for top-ranked quality.
\end{itemize}

A decile-level lift table and cumulative gains curve are produced in the notebook for stakeholder interpretation.

\paragraph{Observed ranking metrics}
\begin{itemize}
    \item Precision@10\%: $0.9775$
    \item Base conversion rate (random expectation): $0.4792$
    \item Lift@10\%: $2.0401$
    \item NDCG@10\%: $0.9795$
\end{itemize}

Top-decile precision is roughly two times the random baseline rate, indicating strong ranking utility for prioritization.

\subsubsection{Validation Stability (Time-Based Folds)}

\textbf{What a ``fold'' means here.} The modeling table is keyed by \texttt{season} with two values (\texttt{winter\_spring} and \texttt{summer\_autumn}). A time-based fold trains on one season and tests on the other. Because there are exactly two seasons, we evaluate \textbf{two folds}:
\begin{itemize}
    \item Fold A: train \texttt{winter\_spring} $\rightarrow$ test \texttt{summer\_autumn}
    \item Fold B: train \texttt{summer\_autumn} $\rightarrow$ test \texttt{winter\_spring}
\end{itemize}

\textbf{How this maps to the success criterion.} The criterion compares the \textbf{best vs worst fold} for each metric (not random hold-out vs a single temporal split). For higher-is-better metrics we report relative gap $(\text{best}-\text{worst})/\text{best}$; for MAE (lower is better) we report $(\text{worst}-\text{best})/\text{best}$.

\paragraph{Observed fold metrics (best models)}
\begin{itemize}
    \item Fold A (winter$\rightarrow$summer), Gradient Boosting / Random Forest: \texttt{macro-F1} $=0.8094$, \texttt{ROC-AUC} $=0.9086$, regression \texttt{MAE} $=0.0824$, $R^2=0.4425$.
    \item Fold B (summer$\rightarrow$winter), same models: \texttt{macro-F1} $=0.8549$, \texttt{ROC-AUC} $=0.9404$, regression \texttt{MAE} $=0.0847$, $R^2=0.5774$.
\end{itemize}

\paragraph{Best vs worst fold gaps}
\begin{itemize}
    \item \texttt{macro-F1}: about $5.33\%$ gap (passes the 15\% rule).
    \item \texttt{ROC-AUC}: about $3.38\%$ gap (passes).
    \item \texttt{MAE}: about $2.73\%$ gap (passes).
    \item $R^2$: about $23.36\%$ gap (\textbf{fails} the 15\% rule).
\end{itemize}

So: training only on \texttt{winter\_spring} and testing on \texttt{summer\_autumn} is a valid \emph{single} temporal evaluation, but it is not sufficient by itself to satisfy the written ``best vs worst fold'' rule; the notebook therefore reports \textbf{both} directions.

\subsubsection{Feature Interpretability}

Interpretability is produced via permutation importance on the hold-out split for the best classification model. The top-5 features are reported with their mean importance and variance, providing a stakeholder-readable explanation of which repository signals drive conversion predictions.

\paragraph{Top-5 features (permutation importance, macro-F1 impact)}
\begin{itemize}
    \item \texttt{n\_pr\_events} (dominant signal; mean importance $\approx 0.3261$)
    \item \texttt{issue\_comments\_winsor} ($\approx 0.00166$)
    \item \texttt{n\_forks} ($\approx 0.00148$)
    \item \texttt{issue\_comments} ($\approx 0.00114$)
    \item \texttt{season\_winter\_spring} ($\approx 0.00097$)
\end{itemize}

The model is primarily driven by PR-event intensity and supported by interaction/fork activity features.

\subsubsection{Sensitivity Check (90-Day Observation Window Only)}

All exported labels in this project correspond to a \textbf{single fork-to-PR observation window of 90 days} (Data Preparation: \texttt{OBSERVATION\_DAYS = 90}). The modeling notebook does not mix multiple window definitions.

Therefore, the formal ``alternative observation windows'' sensitivity criterion is \textbf{not re-measured inside this notebook}. To assess sensitivity to a different window length, Stage~3 must be re-run to export an alternate label column; that check is intentionally outside this notebook so the modeling stage stays aligned with one fixed label contract.

\subsubsection{Practical Interpretation}

\begin{itemize}
    \item Tree ensembles provide flexible non-linear modeling for heavy-tailed repository activity.
    \item Logistic/linear models provide a transparent baseline for communication to non-technical stakeholders.
    \item Baseline comparisons prevent over-claiming improvements in an imbalanced, noisy environment.
\end{itemize}

\subsubsection{Limitations}

\begin{itemize}
    \item Time-based validation uses two seasonal folds (both train/test directions). This matches the ``best vs worst fold'' wording, but still provides only two temporal regimes; richer multi-fold checks require exporting additional time slices.
    \item Regression $R^2$ fails the 15\% best-vs-worst-fold stability rule in this sample, even though classification metrics pass.
    \item Target construction remains based on heuristic fork-to-PR matching and may contain residual label noise.
    \item Extreme conversion ratios in low-fork repositories can still challenge regression stability.
\end{itemize}

\subsubsection{Hyperparameter Tuning Outcome}

Randomized search was run for Random Forest models.
\begin{itemize}
    \item Tuned RF \textbf{classification}: \texttt{macro-F1} $=0.8503$, \texttt{ROC-AUC} $=0.9322$.
    \item Tuned RF \textbf{regression}: \texttt{MAE} $=0.0750$, $R^2=0.6338$.
\end{itemize}

Interpretation:
\begin{itemize}
    \item For classification, tuning RF did not surpass Gradient Boosting (\texttt{macro-F1} $=0.8514$).
    \item For regression, tuning gave a small improvement in $R^2$ over the initial RF model.
\end{itemize}
